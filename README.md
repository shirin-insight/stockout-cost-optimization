# The Invisible Cost of Stockouts
### A reproducible inventory analytics and policy simulation project

**Author:** `shirin-insight`  
**Focus:** Data analytics · Operations research · Inventory management · Simulation

## Why this project?
A stockout is more than an empty shelf: it can mean lost sales, emergency replenishment, and customers who cannot buy what they came for. This project builds a transparent, reproducible simulation to compare inventory policies under uncertain demand and supplier lead times.

Unlike a generic sales dashboard, the project asks a decision question:

> Under the same demand and lead-time conditions, how do simple reorder policies trade off service level, inventory holding cost, and estimated lost-sales cost?

## Important data note
The included dataset is **synthetic**, generated by `src/generate_data.py` with a fixed random seed. It is not company data and should not be interpreted as evidence about a real retailer. Synthetic data makes the repository runnable without credentials or external downloads; the analysis pipeline can later be adapted to a documented public dataset.

## What it does
1. Generates two years of daily demand for 24 products with different demand levels, weekly patterns, seasonality, and occasional demand spikes.
2. Generates supplier lead times and product-level unit costs.
3. Simulates three reorder policies using the same demand series:
   - **Baseline:** reorder point based on average demand during lead time plus a modest safety buffer.
   - **Higher safety stock:** larger buffer intended to improve availability.
   - **Lean inventory:** smaller buffer intended to reduce average inventory.
4. Reports service level, lost units, holding-cost proxy, estimated lost-sales cost, and a combined cost proxy.
5. Exports CSV summaries and charts for easy review.

## Quick start
Python 3.10+ recommended.

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux:
source .venv/bin/activate
pip install -r requirements.txt
python src/generate_data.py
python src/analyze.py
```

The scripts write all generated data and results inside this repository. Re-running the generator with the same seed should reproduce the same input data.

## Definitions and assumptions
- **Demand** is generated as non-negative daily unit demand.
- **Lead time** is sampled for each replenishment order from a product-specific range.
- **Lost sales** are used rather than backorders: unmet demand is not carried to later days.
- **Holding cost proxy** is average on-hand inventory multiplied by unit cost and an annual carrying-rate assumption, scaled to the simulation horizon.
- **Lost-sales cost proxy** is unmet units multiplied by an assumed gross-margin proxy.
- **Combined cost proxy** is holding-cost proxy plus estimated lost-sales cost. It is a simplified comparison metric, not accounting profit.
- Policies are compared on the same demand history. This is a scenario simulation, not a causal estimate.
- The model uses a periodic daily review and a simplified replenishment process. Real operations may require order batching, minimum order quantities, supplier calendars, and demand censoring adjustments.

## Validation checks
`src/analyze.py` checks that:
- input demand is non-negative and dates are unique per product;
- policy metrics are within plausible bounds;
- service level lies between 0 and 1;
- the policy comparison contains all configured policies.

## Suggested extensions
- Replace synthetic demand with an openly licensed dataset and cite its source.
- Add demand forecast uncertainty and compare forecast-based reorder points.
- Use bootstrap intervals to show how sensitive policy rankings are to the selected demand period.
- Add a SQL layer or a Power BI dashboard.
- Add a unit-test suite and CI workflow.

## Data generation and reproducibility
The generator uses a fixed seed (`20261016`). All simulated values are created locally; no external API is required.
